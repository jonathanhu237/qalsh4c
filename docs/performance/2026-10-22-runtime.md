# Runtime optimization measurements — 2026-10-22

This change targets complete QALSH sampling runs: index construction, approximate
weight generation, and exact distances for sampled points. It preserves the
algorithm, sampling configuration, point order, and persistent index format.

## Changes retained

- Bounded L1/L2 distances check the bound after blocks of 16 coordinates while
  preserving ordered float additions and separately rounded products. Vectors
  of at most 16 coordinates retain the original per-coordinate checks. NaNs
  replay the scalar loop to preserve early-pruning behavior.
- Index builders copy points into batches of about 4 MiB, then project them with
  reusable workers. Accessors still run once per point, in order, on the caller's
  thread, so an accessor backed by one scratch buffer remains valid. Small
  workloads and one-worker builds retain the serial path.
- Disk construction uses sequential point reads and honors the CLI thread
  count. B+ tree descent uses binary search over separators with the same
  equality rule as before.

Three collision-counter loop alternatives were evaluated and discarded because
they were slower or indistinguishable from the original loop in isolated weight
generation runs. The production collision driver is unchanged.

## Measurement method

The frozen baseline is commit `dd5138f`; the optimized source is the commit
containing this report. Both executables were built on Centaurus with GCC
15.2.0, CMake 4.2.3, Ninja, `-O3 -DNDEBUG -march=native -g`, OpenMP enabled, and
`QALSH4C_ENABLE_CUDA=OFF`. The server has an AMD Ryzen 9 5900X (12 cores,
24 hardware threads) and runs Linux 7.0.0-31-generic.

Measurements use process wall time, alternate baseline and optimized runs,
and exclude input preparation, hashing, and correctness checks. Each case has
one warmup per executable. No other experiment or build runs concurrently.
CPU frequency scaling remains enabled. `OMP_PROC_BIND=false` is set for both
executables so build workers do not inherit a single OpenMP thread's CPU
affinity. These are warm OS-cache measurements; no kernel cache flushing is
performed.

The main matrix uses five measured repetitions per executable, A→B, fixed
random seeds, approximation ratio 2, and 512 samples. `cold` means the weight
file is deleted before each run, so the process includes building the in-memory
index and regenerating weights. `cached` reuses the weight file and primarily
measures exact sampled distances plus process startup and input loading.
It does not mean cold filesystem or device caches.

| Input | A points | B points | Dimensions | Origin |
|---|---:|---:|---:|---|
| MNIST | 3,000 | 66,900 | 784 | Float32 server MNIST base, split in original order |
| GMM128 | 4,000 | 20,000 | 128 | CLI generator, seed 42, outlier fraction 0.1, scale 4096 |
| Federalist | 1,880 | 1,178 | 300 | Committed `data/federalist` |
| GMM32 / GMM2 | 4,000 | 20,000 | 32 / 2 | Same GMM options with the indicated dimension |

Input metadata, SHA-256 hashes, executable hashes, exact commands, estimates,
and individual timing rows accompany this report. MNIST uses the float32
`~/datasets/qalsh-h/mnist/base.bin` on Centaurus, rather than any older
double-encoded local copy. The split helper records the resulting hashes.
Recorded CSV line endings are normalized to LF for version control; all
parsed fields remain unchanged.

## Results

The tables below report medians of whole-process wall time. A ratio above 1
means the optimized executable is faster. Small differences should be read
with the individual repetitions, especially for sub-10-ms cases.

### Persistent index construction and disk sampling

These cases use three repetitions per executable, 512 samples, index seed
1608637542 (matching the in-memory fixed-seed build), 16-KiB index pages,
4096-byte point-read blocks, and query batches of 64. Every iteration rebuilds the index and regenerates
weights. Total time is the median of each iteration's paired build plus
sampling process times, not the sum of the two separate medians. Hashing the
index before sampling warms its file cache equally for both executables.

On the larger inputs, eight-thread index construction is 2.61–3.12× faster;
the complete build-plus-sampling workload saves 13.8%–20.2%. These measurements
describe warm-cache disk-backed execution, not storage throughput with cold
device caches.

## Correctness and scope

- The native Release build passes all 32 CTest tests, including new checks of
  bounded distances against a frozen scalar reference, candidate order and
  counters, duplicate B+ tree separators, and parallel builder failures.
- The bounded-distance tests compare float bits for L1/L2, block boundaries,
  short vectors, large dimensions, exact threshold equality, adjacent float
  bounds, infinities, NaNs, and difficult magnitudes. Both raw-pointer and
  vector entry points are covered where their original contracts coincide.
- Serial and parallel builds produce identical projections and search results;
  both persistent layouts produce byte-identical files. Tests exercise an
  owner-thread-only accessor that overwrites one scratch buffer, multiple
  batches, uneven tails, accessor errors, and projection overflow.
- Every benchmark run verifies identical weight-file hashes. Single-thread
  estimator comparisons use the CLI's displayed values (six decimals), not an
  unexposed internal bit pattern. Multithreaded estimates allow relative error
  `2e-6` because OpenMP reductions can associate the same terms differently.
- The pre-existing grouped-versus-single SIMD dot-product equality assertion
  also failed in the unchanged baseline with native compiler flags. It now
  checks both results against an extended-precision reference and a standard
  floating-point forward-error bound. Projection arithmetic was not changed.
- Numerical compatibility claims here concern the tested GCC configurations.
  Other compilers' bitwise behavior and speedups on other machines are not
  established by these measurements.

The four focused distance, projection, build, and query tests also pass in a
portable GCC Release build (`-O3 -DNDEBUG`, without `-march=native`). The
parallel build test passes under GCC ThreadSanitizer (`-O1 -g
-fsanitize=thread -fno-omit-frame-pointer`) with `halt_on_error=1`, including
its accessor/worker failure cases; no data race was reported. An independent
OpenSpec review found no actionable implementation defect.

## Reproduction

Keep the baseline executable before editing or rebuilding its source. To
reproduce from Git, create a local source snapshot of `dd5138f`, synchronize
that snapshot one-way to a build directory inside `~/code/qalsh4c` on
Centaurus, and build there. Synchronize the current local source to the normal
Centaurus checkout and build the optimized executable separately. Use the
same compiler and flags for both:

```sh
cmake -S . -B build/perf-after -G Ninja \
  -DCMAKE_BUILD_TYPE=Release \
  '-DCMAKE_CXX_FLAGS_RELEASE=-O3 -DNDEBUG -march=native -g' \
  -DQALSH4C_ENABLE_CUDA=OFF -DBUILD_TESTING=ON
cmake --build build/perf-after -j8
ctest --test-dir build/perf-after --output-on-failure -j8
```

Prepare inputs on Centaurus. The MNIST helper refuses to overwrite an existing
output directory. GMM2 and GMM32 use the same generation command with a changed
dimension and output directory.

```sh
python3 scripts/prepare_runtime_mnist.py \
  --source "$HOME/datasets/qalsh-h/mnist" \
  --output build/perf-data/mnist784 --num-points-a 3000
build/perf-before/qalsh4c dataset generate gmm \
  --num-points-a 4000 --num-points-b 20000 --num-dimensions 128 \
  --outlier-fraction 0.1 --outlier-scale 4096 --seed 42 \
  -o build/perf-data/gmm128
python3 scripts/benchmark_runtime.py \
  --before build/perf-before/qalsh4c --after build/perf-after/qalsh4c \
  --dataset mnist784=build/perf-data/mnist784 \
  --dataset gmm128=build/perf-data/gmm128 --dataset federalist=data/federalist \
  --threads 1 8 --norms 1 2 --repeats 5 \
  --output build/perf-evidence/runtime-final.csv
```

The benchmark scripts require Python 3.11 or newer. Their temporary dataset
directories are removed on exit; recorded command paths identify the original
runs, while the script options above recreate equivalent isolated fixtures.
The original dataset caches are not modified.

Additional build checks:

```sh
cmake -S . -B build/perf-portable -G Ninja -DCMAKE_BUILD_TYPE=Release \
  '-DCMAKE_CXX_FLAGS_RELEASE=-O3 -DNDEBUG' \
  -DQALSH4C_ENABLE_CUDA=OFF -DBUILD_TESTING=ON
cmake --build build/perf-portable -j8 --target \
  distance_bounds_test qalsh_build_test qalsh_distance_test qalsh_query_speed_test
ctest --test-dir build/perf-portable --output-on-failure \
  -R '^(distance_bounds_test|qalsh_build_test|qalsh_distance_test|qalsh_query_speed_test)$'
cmake -S . -B build/perf-tsan -G Ninja -DCMAKE_BUILD_TYPE=RelWithDebInfo \
  '-DCMAKE_CXX_FLAGS_RELWITHDEBINFO=-O1 -g -fsanitize=thread -fno-omit-frame-pointer' \
  -DQALSH4C_ENABLE_CUDA=OFF -DBUILD_TESTING=ON
cmake --build build/perf-tsan -j8 --target qalsh_build_test
TSAN_OPTIONS=halt_on_error=1 ctest --test-dir build/perf-tsan \
  --output-on-failure -R '^qalsh_build_test$'
```
